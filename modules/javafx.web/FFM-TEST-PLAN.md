# javafx.web JNI -> FFM: the verification plan

Companion to `FFM-ABI-CONTRACT.md`. The contract says what the ABI is; this document says how any
of it is *proved*, what cannot be proved in this repository, and exactly which tests get written.
It is binding on the agents implementing the migration: the Java test classes in section 4 are a
specification, not a menu.

Status of the non-Java half: **built and verified on this machine** (Windows x64, MSVC 19.44,
CMake 3.24.2, JDK 26). Sections 2 and 3 describe what exists; sections 4 and 5 are the work order.

---

## 1. The problem, stated honestly

### 1.1 Baseline

Recorded on branch `ffm/web` before any migration change, and re-measured after the build wiring
in section 3 was applied - identical both times:

```
mvn -pl modules/javafx.web test -Djfx.web.skipTests=false
[ERROR] Tests run: 473, Failures: 1, Errors: 0, Skipped: 113
[ERROR]   LoadTest.loadJarFile:373 -> netscape.javascript.JSException:
          ReferenceError: Can't find variable: jsc0
```

That one failure is pre-existing and unrelated to this migration. The library under test is the
prebuilt `../caches/sdk/bin/jfxwebkit.dll`, which exports **1956 `Java_com_sun_*` JNI symbols and
zero `wkj_*` symbols**.

### 1.2 What this repository can verify

`modules/javafx.web` compiles Java only. Nothing in any pom configures the WebKit CMake/Ninja
tree, and this fork cannot build it. So the migration splits into a half that is genuinely
executed here and a half that is not:

| Artefact | Verified here? | How |
|---|---|---|
| `WebKitNative` and the generated `*Native` facades compile | yes | `mvn -pl modules/javafx.web install` |
| Every bound symbol resolves | yes, against `wkjstub` | section 4.2 |
| Every `FunctionDescriptor` matches the ABI | yes, twice over | section 4.3 |
| `WKJExceptionSlot` / `WKJHost` layouts vs C `sizeof`/`offsetof` | yes, against `wkjstub` | section 4.4 |
| UTF-16 marshalling, null vs empty, non-ASCII, surrogates | yes, real downcalls | section 4.6 |
| Exception-slot decode, type/code/message | yes | section 4.7 |
| The Java object registry and its emptiness after dispose | yes | section 4.8 |
| Upcalls through the host table, including from a foreign OS thread | yes | section 4.9 |
| Arena lifetime and confinement failures | yes | section 4.10 |
| That the **C++ side compiles** | **no** | needs the WebKit toolchain |
| That the C++ side *behaves* the same as the JNI it replaces | **no** | needs a rebuilt `jfxwebkit` |
| The 473 module tests | **no**, until `jfxwebkit` is rebuilt | section 5 |
| DumpRenderTree / LayoutTests | **no** | needs a WebKit build; manual run |
| The robot web tests in `tests/system` | **no** | needs a rebuilt `jfxwebkit` + a display |

The Java half is verified against `wkjstub` (section 2): a generated recording library that
implements the whole `wkj_*` ABI. That is a real, loaded, executed shared library - not a mock -
so symbol resolution, every descriptor, every string round trip, the exception slot, the registry
and the upcall table are exercised for real, with real memory and real ABI rules.

### 1.3 What the reviewer must take on trust

Precisely three things, and no more:

1. **The C++ implementation compiles.** No build in this repository compiles
   `Source/WebKitLegacy/java/**`, `Source/WebCore/**/java/**` or `Source/WTF/wtf/java/**`.
   Mitigations: the DOM half is generated by script from `buildtools/ffm-web/dom-cpp-to-ffm.pl`,
   and `spec-to-header.pl`'s output has been compiled standalone with MSVC as both C and C++ at
   `/W4 /WX`. The stub compiles the same declarations. None of that is a substitute for building
   WebKit.
2. **The C++ implementation behaves as the JNI did.** `wkjstub` proves the *shape* of every call;
   it says nothing about whether `wkj_dom_Node_getNodeName` returns the node's name. Only the 473
   module tests against a rebuilt `jfxwebkit` prove that, and they cannot run here.
3. **The ABI spec matches the C++ sources.** `dom-abi.tsv` is derived mechanically from the DOM
   binding sources, and the generator cross-checks each row's C types against its declared FFM
   layouts (section 2.3), so a spec that is internally inconsistent fails the build. A spec that is
   *consistently wrong about the sources* would not be caught here.

Everything else in the Java half is executed, not asserted.

## 2. `wkjstub`: the stub native library

`modules/javafx.web/src/test/native/wkjstub/`. Test-only: never packaged, never installed, named
`wkjstub` and not `jfxwebkit` so it can neither be confused with nor shadow a real WebKit library.

### 2.1 What it is

A shared library that implements every `wkj_*` function with a recording stub: it copies its
arguments into a ring buffer, returns a safe default (or a value a test programmed for it), and
exposes the recording through a second, `wkjstub_*`-prefixed query ABI. Built here it produces:

```
wkjstub.dll: 1799 wkj_* exports (1796 DOM + wkj_init, wkj_abi_version, wkj_exception_slot)
             49 wkjstub_* query exports + 52 wkjstub_sizeof_* / wkjstub_offsetof_* exports
             15 structs and 19 host-table slots described in enumerable tables
```

### 2.2 Files

| File | Role |
|---|---|
| `gen-wkjstub.pl` | the generator; reads the core ABI header and the DOM spec, writes `wkjstub_generated.c` |
| `wkjstub.h` | types shared between the runtime and the generated code; the kind alphabet |
| `wkjstub_runtime.c` | hand-written: ring buffer, exception slot, host storage, the `wkjstub_*` query ABI, and the three `wkj_*` functions that need real behaviour |
| `seed/webkit_java_api.h` | scaffolding: a core-ABI-shaped header used only while the real one does not exist. **Declares no DOM function and never may** |
| `CMakeLists.txt` | the build; prefers the real core header, generates the DOM header from the spec |

### 2.3 It is generated, and from the right source

The stub is never hand-written, because a hand-written stub encodes a *guess* at a signature, and
a wrong guess is agreed to by a wrong `FunctionDescriptor`: the test passes and the real library
corrupts memory. The two halves therefore come from two different, non-guessable sources:

* **DOM half** - `buildtools/ffm-web/dom-abi.tsv`, derived from the DOM binding sources by
  `dom-cpp-to-ffm.pl`. 1831 rows, of which 1796 are `BUILT=1`. The generator **skips `BUILT=0`
  rows**: those come from sources that are not compiled into the library, so the library does not
  export them and the stub must not either - otherwise symbol resolution would pass here and fail
  against the real `jfxwebkit`.
* **Core half** - `Source/WebKitLegacy/java/api/webkit_java_api.h`, parsed for its `WKJ_EXPORT`
  declarations, its struct typedefs and its `WKJHost` tree. When that file does not exist the
  build falls back to `seed/webkit_java_api.h` and prints a CMake warning saying the core binding
  tests are provisional. (It exists as of this writing; the fallback is kept for bisects.)

The generator is deliberately strict, because every strictness is a check that runs on every build:

* an unrecognised C type is fatal, not a guess - so `long`, `size_t` and platform types cannot
  enter the ABI unnoticed (`FFM-ABI-CONTRACT.md` section 2 requires `<stdint.h>` types);
* each spec row's `RET_LAYOUT` / `PARAM_LAYOUTS` is cross-checked against the kind derived from
  the row's C types, and a disagreement is fatal. This is what would have caught the earlier
  `wkj_dom_Element_getScrollTop` mistake (`double` in a hand-written header where the JNI is
  `jint`) at build time;
* a symbol declared in both the core header and the spec is fatal;
* a function-pointer parameter in an exported function is fatal (it would break the flat ABI);
* more than 24 parameters is fatal (the recording arity limit).

Conventions the generator recognises and *documents in a comment above each generated body*, so a
reviewer can check them: `const uint16_t* s, int32_t s_len` is a UTF-16 string argument (contents
copied at call time); `const T* data, int32_t len` is a primitive array (bytes copied); a
`const uint16_t*` return with a trailing `int32_t*` parameter is the out-length string return; an
`int32_t` return with trailing `T* out, int32_t *cap*` is a fill-an-array call.

### 2.4 Runtime behaviour that matters to tests

* **One recorded argument per C parameter**, so recorded argument indices line up with
  `FunctionDescriptor` argument indices. Kinds are `v b h i l f d p` plus `s` (UTF-16 string,
  payload copied) and `a` (array, payload copied). Floats and doubles are recorded as raw bit
  patterns; Java decodes with `Float.intBitsToFloat` / `Double.longBitsToDouble`.
* **Null and empty are distinguishable at the boundary.** `wkjstub_call_arg_string` returns `NULL`
  with `*out_length == -1` for a `NULL` argument and a valid pointer with `*out_length == 0` for
  the empty string. The library collapses both to the empty `WTF::String` on the way in, but the
  ABI still carries the distinction and the facade must pass `NULL` for a Java `null`; that is
  what this export lets a test assert.
* **String returns use the caller's buffer** (`webkit_java_api.h` section 2, contract 13):
  `int32_t f(..., uint16_t* result_buf, int32_t result_cap, int32_t* result_length)` returning
  `WKJ_STR_OK` / `WKJ_STR_NULL` / `WKJ_STR_OVERFLOW`. The stub implements all three, including
  writing the required capacity into `*result_length` on overflow, so the facade's
  grow-once-and-retry path is executed rather than assumed. There is no library-owned string
  memory and therefore no lifetime rule to test.
* **The exception slot is per thread**, returned by `wkj_exception_slot()`, with the message
  inline (`uint16_t message[WKJ_EXC_MESSAGE_MAX]`, truncating at 256 code units).
  `wkjstub_record` **clears the slot on entry to every `wkj_*` call**, exactly as the header
  specifies, and `wkjstub_arm_exception(name, ...)` schedules a one-shot exception that fires when
  the named function is next called - the real control flow, not a poke.
* **`wkj_init` implements the contract's checks and result codes exactly**: `WKJ_INIT_ERR_NULL_HOST`,
  then `WKJ_INIT_ERR_ABI_VERSION`, then `WKJ_INIT_ERR_HOST_SIZE` (which requires
  `host_size == sizeof(WKJHost)` **and** `host->size == host_size`, so a Java-side layout that
  disagrees with the C struct is rejected here), then `WKJ_INIT_ERR_ALREADY_INITED`. It also sets
  the `wkj_host` global the header declares.
* **Upcalls are dispatched by a generated typed switch.** `wkjstub_fire_host(slot, argv, argc, out)`
  calls any installed host callback with the correct C signature; `argv` carries one `int64_t` per
  parameter (integers sign-extended, floats/doubles as raw bits, pointers as addresses) and `out`
  receives the return the same way. Status: `0` ok, `-1` unknown slot, `-2` slot is `NULL`,
  `-3` wrong argument count, `-4` no host installed, `-5` (threaded variant) thread start failed.
* **`wkjstub_fire_host_on_foreign_thread`** does the same from an OS thread the JVM has never
  seen - the case JNI needed `AttachCurrentThread` for, and the one WebKit's worker threads will
  actually take.
* Thread-safe (SRWLOCK on Windows, `pthread_mutex` elsewhere); ring capacity 1024, with
  `wkjstub_call_total()` exposed separately so a test can detect overflow.

### 2.5 The `wkjstub_*` query ABI

All signatures are flat C. `const uint16_t* name, int32_t name_length` is a UTF-16 name;
returned strings follow the same out-length convention as the real ABI.

| Group | Exports |
|---|---|
| control | `wkjstub_stub_version()`, `wkjstub_reset()`, `wkjstub_clear_returns()`, `wkjstub_clear_host()`, `wkjstub_set_abi_version(v)`, `wkjstub_ring_capacity()` |
| recording | `wkjstub_call_count()`, `wkjstub_call_total()`, `wkjstub_call_name(i, out_len)`, `wkjstub_call_argc(i)`, `wkjstub_call_arg_kind(i, a)`, `wkjstub_call_arg(i, a)`, `wkjstub_call_arg_is_null(i, a)`, `wkjstub_call_arg_string(i, a, out_len)`, `wkjstub_call_arg_bytes(i, a, out, cap)`, `wkjstub_find_call(name, len, from)`, `wkjstub_count_calls(name, len)` |
| programmed returns | `wkjstub_set_return_i64`, `wkjstub_set_return_f64`, `wkjstub_set_return_string` (`NULL` value programs a Java `null`), `wkjstub_set_return_bytes` |
| exceptions | `wkjstub_raise(type, code, msg, len)`, `wkjstub_arm_exception(name, len, type, code, msg, len)`, `wkjstub_exception_pending()` |
| host table | `wkjstub_host_installed()`, `wkjstub_host_size()`, `wkjstub_host_abi_version()`, `wkjstub_host_init_result()`, `wkjstub_host_slot_count()`, `wkjstub_host_slot_name(i, out_len)`, `wkjstub_host_slot_signature(i, out_len)`, `wkjstub_host_slot_offset(i)`, `wkjstub_host_slot_pointer(i)`, `wkjstub_find_host_slot(name, len)`, `wkjstub_fire_host(...)`, `wkjstub_fire_host_on_foreign_thread(...)` |
| ABI description | `wkjstub_symbol_count()`, `wkjstub_symbol_name(i, out_len)`, `wkjstub_symbol_signature(i, out_len)`, `wkjstub_symbol_throws(i)` |
| layouts | `wkjstub_struct_count()`, `wkjstub_struct_name(i, out_len)`, `wkjstub_struct_size(i)`, `wkjstub_struct_field_count(i)`, `wkjstub_struct_field_name(i, f, out_len)`, `wkjstub_struct_field_offset(i, f)`, `wkjstub_struct_field_size(i, f)`, `wkjstub_struct_field_kind(i, f)`, `wkjstub_struct_field_elements(i, f)`, plus a `wkjstub_sizeof_<Struct>()` and `wkjstub_offsetof_<Struct>_<field>()` per struct and field |

A signature string is the return kind followed by one kind per parameter: `wkj_dom_Attr_setValue`
is `"vlpi"`, `wkj_dom_Attr_getName` is `"ilpip"`, `wkj_dom_Node_getNodeType` is `"hl"`. For a
struct field, `_kind` is the *element* kind and `_elements` is 1 for a scalar or the extent for an
array, so `WKJExceptionSlot.message` reports kind `h` with 256 elements -
`MemoryLayout.sequenceLayout(256, JAVA_CHAR)`.

### 2.6 Evidence that it works

Built clean at `/W3 /WX` with MSVC 19.44 and exercised end to end through FFM from `jshell`
(scratch script, not committed). Observed:

```

string arguments  null / "" / "abc" / "日本語" / "a"+NUL+"b" / "😀"  -> all six round-tripped;
                  isNull=1 only for null; "" arrived as a non-NULL pointer of length 0;
                  the embedded NUL survived as 3 code units
string returns    OK: status=0 len=3 value="日本語"
                  OVERFLOW: status=2 required=10; retry with a 10-unit buffer -> status=0
                  NULL: status=1 len=0 ; EMPTY: status=0 len=0
exception slot    armed on wkj_dom_Attr_setValue -> type=1 code=8 message_length=16,
                  last code unit 0x65E5 ; cleared on entry to the next wkj_* call
layouts           offsetof(message)=12 matches; C sizeof=524; the C table reports
                  message as kind 'h' with 256 elements
host table        sizeof(WKJHost)=160, 19 slots, wkj_init=0
```

Every mechanism section 4 depends on has therefore already run once. One incidental finding worth

bytes against the C's 524, because it carried a trailing `paddingLayout(4)` the C struct does not
need (three `int32_t` then `uint16_t[256]`, alignment 4). That is exactly the class of error test
4.4 exists to catch, and it caught one on its first run.

## 3. Build wiring (applied)

Minimal and additive; `modules/javafx.web/pom.xml` only. Verified afterwards:
`mvn -pl modules/javafx.web install -DskipTests` succeeds (15 s including a from-scratch stub
build; 6-7 s with the stub build skipped), and
`mvn -pl modules/javafx.web test -Djfx.web.skipTests=false` still reports exactly
**473 tests, 1 failure (`LoadTest.loadJarFile`), 113 skipped**.

1. **New properties.** `jfx.web.skipFfmTests` (default `false`) and `jfx.web.stub.bindir`
   (`${project.build.directory}/native/bin`).
2. **Two profiles**, `web-stub-native-win` and `web-stub-native-unix`, activated by OS family
   **and** `skipNative != true` - the same idiom `modules/javafx.graphics/pom.xml` uses. Each runs
   `cmake -S src/test/native/wkjstub -B target/native/cmake` and `cmake --build` at phase
   `generate-test-resources`, both gated by `<skip>${jfx.web.skipFfmTests}</skip>`. The library
   lands in `modules/javafx.web/target/native/bin/wkjstub.dll`.
3. **Two surefire executions.**
   * `default-test` keeps `skipTests=${jfx.web.skipTests}` and adds `<excludedGroups>ffm</excludedGroups>`.
   * `ffm-binding-test` runs `<groups>ffm</groups>` with `skipTests=${jfx.web.skipFfmTests}` and
     its own `argLine`: identical to the module's, except
     `-Djava.library.path=${jfx.web.stub.bindir}${path.separator}${jfx.native.librarypath}`
     (stub directory **first**), `-Djavafx.web.nativeLibrary=wkjstub`, and
     `-Djfx.web.dom.abi.spec=${jfx.root}/buildtools/ffm-web/dom-abi.tsv`.

Tags rather than path excludes, deliberately: `-Dtest=Foo` overrides surefire's includes/excludes
but not its tag filters, so a developer narrowing to one test still gets it in exactly one
execution, with the right library.

**No collision with a real `jfxwebkit`**: different library name, a separate JVM fork, and the
stub directory only prepended in that fork. `../caches/sdk/bin` stays on the path for
`javafx.graphics`/`javafx.media`, and nothing loads `jfxwebkit` in the FFM fork.

How to run:

```bash
mvn -pl modules/javafx.web test                              # builds wkjstub, runs the FFM tests
mvn -pl modules/javafx.web test -Dgroups=ffm                 # the same, explicitly
mvn -pl modules/javafx.web test -Djfx.web.skipTests=false    # the 473 as well (needs jfxwebkit)
mvn -pl modules/javafx.web test -Djfx.web.skipFfmTests=true  # no stub build, no FFM tests
mvn -pl modules/javafx.web test -DskipNative=true            # no stub build; FFM tests self-skip
```

### 3.1 The one production hook this requires

`WebKitNative` must take its library name from a system property:

```java
private static final String LIBRARY_NAME = System.getProperty("javafx.web.nativeLibrary", "jfxwebkit");
```

One line, at the single place that calls `NativeLibLoader.loadLibrary(...)` (today
`WebPage`'s static initializer, line 130). It is the only production change the test plan needs.
The alternative - naming the stub `jfxwebkit` and shadowing the real one on the library path - was
rejected: it makes "which library did I just test?" unanswerable from a log.

## 4. The Java test specification

Rules for every class below: package `test.com.sun.webkit.ffm`, JUnit 5, `@Tag("ffm")` on the
class, GPLv2+CPE header, no wildcard imports except static assertion imports, <= 120 columns,
`--release 25`. Each class begins with

```java
@BeforeAll static void loadLibrary() { assumeTrue(WkjStubShim.load(), WkjStubShim.loadFailure()); }
```

so the suite skips (rather than fails) when `-DskipNative=true` left no stub built. Test code runs
in the unnamed module and must make **no** restricted FFM call: everything goes through the two
shims below.

### 4.0 Shims the Java agent writes first

**`com.sun.webkit.WkjStubShim`** - `modules/javafx.web/src/shims/java/com/sun/webkit/WkjStubShim.java`.
The whole driver for the `wkjstub_*` query ABI, and the only place in test-facing code that calls
`Linker`, `SymbolLookup` or `Arena`. It is compiled into `javafx.web`, so
`--enable-native-access=javafx.web` (already in the argLine) covers it. Required surface, all
static, all plain Java types:

**`com.sun.webkit.WebKitNativeShim`** - exposes what is package-private in `WebKitNative`:

```

                                           // ("v b h i l f d p" per section 2.5), or null
```

`boundSymbols()` and `descriptorOf()` must work **without the library being loaded**, so the
facades' descriptor metadata has to be constructible independently of their `MethodHandle`s. That
is a design constraint on the facade generator, and it is what makes 4.3 a one-test check of 1796
functions.

### 4.1 `WkjStubLibraryTest` - the stub is sane (pattern 3)

Everything else trusts the stub, so a broken stub must fail here and not as noise elsewhere.

* `wkjstub_stub_version() == 1`.
* After `reset()`: `callCount() == 0`, `callTotal() == 0`.
* Drive one `wkj_dom_*` call through the facade, then assert `callCount() == 1`,
  `callName(0)` is the expected symbol, `callArgc(0)` equals the descriptor's argument count.
* Ring overflow is visible: make `ringCapacity() + 5` calls, assert
  `callCount() == ringCapacity()` and `callTotal() == ringCapacity() + 5`, and that `callName(0)`
  is the oldest *retained* call, not the oldest call.
* `symbolCount() >= 1796` and every `symbolName(i)` is non-empty and starts with `wkj_`.

### 4.2 `WebKitNativeSymbolTest` - symbol resolution (pattern 1)

* For every name in `WebKitNativeShim.boundSymbols()`, assert the loaded library exports it.
  Report *all* missing names in one failure message, not the first.
* The reverse direction: every symbol in the stub's table
  (`symbolName(0..symbolCount())`) that the DOM spec marks `BUILT=1` is bound by some facade.
  A symbol in the library that Java never binds is a warning, not a failure (the core ABI grows
  ahead of its callers); a symbol Java binds that the library does not export is a failure.
* `boundSymbols()` contains no duplicates.
* Assert the three core symbols by name: `wkj_init`, `wkj_abi_version`, `wkj_exception_slot`.
* Negative case: resolving a deliberately absent name throws `UnsatisfiedLinkError` whose message
  contains that name (`FFM-ABI-CONTRACT.md` section 6 / `jni-to-ffm-migration` section 3).

### 4.3 `WebKitAbiDescriptorTest` - descriptors match the ABI (pattern 1/2)

The highest-value test available in this repository: one test, 1796 functions, catching the entire
class of descriptor mismatches that would otherwise be silent memory corruption.

* Read `buildtools/ffm-web/dom-abi.tsv` from `System.getProperty("jfx.web.dom.abi.spec")` (set by
  the surefire argLine); fail if the property is unset or the file is missing - **not** an
  assumption, this file is in the repository.
* Skip `BUILT=0` rows. For every remaining row assert
  `WebKitNativeShim.descriptorOf(SYMBOL)` equals the kind string built from `RET_LAYOUT` and
  `PARAM_LAYOUTS` (`void`->`v`, `JAVA_BYTE`->`b`, `JAVA_SHORT`->`h`, `JAVA_INT`->`i`,
  `JAVA_LONG`->`l`, `JAVA_FLOAT`->`f`, `JAVA_DOUBLE`->`d`, `ADDRESS`->`p`).
* Independently assert the same string equals `WkjStubShim.symbolSignature(...)` for that symbol -
  the C library's own view, derived from the C types, not from the layout columns. Java, spec and
  C must all three agree.
* Assert the row count actually checked is >= 1796, so a truncated or mis-parsed spec fails rather
  than passing vacuously.
* Report every mismatch in one message, capped at the first 50 with a total count.

### 4.4 `WebKitLayoutTest` - layouts vs C `sizeof`/`offsetof` (pattern 2)

* `WebKitNativeShim.exceptionSlotLayout().byteSize() == WkjStubShim.sizeOf("WKJExceptionSlot")`,
  and for each of `type`, `code`, `message_length`, `message`,
  `byteOffset(groupElement(name)) == WkjStubShim.offsetOf("WKJExceptionSlot", name)`.
  `message` is an inline `uint16_t[WKJ_EXC_MESSAGE_MAX]`, so the Java layout must be a
  `sequenceLayout`: assert its element count equals
  `WkjStubShim.structFieldElements(...)` and its byte size equals
  `WkjStubShim.structFieldSize(...)`. Assert there is **no** trailing padding in the Java layout -
  three `int32_t` followed by `uint16_t[256]` needs none, and adding one is the easiest way to get
  this struct wrong (it happened once already, see section 2.6).
* The same for `WKJHost` and every host sub-struct the stub enumerates
  (`structCount()`/`structName(i)`): drive it from the C tables so a new sub-struct is covered
  automatically and an unmatched Java layout fails. Assert `structCount()` equals the number of
  layouts Java declares, so a struct added to the header with no Java layout fails here rather
  than being silently ignored.
* `WebKitNativeShim.hostLayout().byteSize() == WkjStubShim.sizeOf("WKJHost")`, and every host slot
  offset the stub reports equals the offset the Java layout computes for the same dotted path.
* Runs on every platform; this is the cross-platform ABI-drift check.

### 4.5 `WebKitAbiVersionTest` - the version guard (contract section 5)

* Happy path: after `WebKitNativeShim.installHostTable()`,
  `WkjStubShim.hostInitResult() == 0`, `hostInstalled()` is true,
  `hostAbiVersion() == WebKitNativeShim.abiVersionExpected()`.
* Message content, tested directly through `abiVersionMessage(expected, actual)` without touching
  library loading: the string must name the library, both numbers and what to do. Assert it
  contains `"jfxwebkit"` (or the configured library name), the expected version, the actual
  version, and the words `rebuild`/`stale` - assert on substrings, not on the whole sentence.
* Mismatch path, end to end: `WkjStubShim.setAbiVersion(expected + 1)`,
  `WkjStubShim.clearHost()`, then re-run the install path and assert it throws
  `UnsatisfiedLinkError` (contract section 5) whose message is the one above. Restore the version
  in `@AfterEach`.
* Size guard: install a host segment whose `size` field is wrong and assert
  `hostInitResult() == -3` (`WKJ_INIT_ERR_HOST_SIZE`) and that Java reports it rather than
  continuing.
* Re-install guard: installing twice yields `-4` (`WKJ_INIT_ERR_ALREADY_INITED`) and Java does not
  treat it as success.

### 4.6 `WebKitStringMarshallingTest` - UTF-16 (pattern 6)

Drive a real string-taking DOM function (`wkj_dom_Attr_setValue` is the canonical one) and a real
string-returning one (`wkj_dom_Attr_getName`), asserting through the recording. Strings come out
through the caller's buffer with a `WKJ_STR_*` status, so the facade's allocate-and-retry logic is
as much on test here as the encoding is.

**Inputs**, one `@ParameterizedTest` case each. Write every non-ASCII literal as an escape in the
source, so the test file stays ASCII:

| Case | Java literal |
|---|---|
| null | `null` |
| empty | `""` |
| ASCII | `"abc"` |
| non-ASCII | `"\u65E5\u672C\u8A9E"` (Japanese, three characters) |
| embedded NUL | `"a\u0000b"` |
| surrogate pair | `"\uD83D\uDE00"` (`length() == 2`) |
| lone high surrogate | `"\uD83D"` |
| lone low surrogate | `"\uDE00"` |
| long | 70 000 characters, past any 64 KiB assumption |

Arguments in:

* `WkjStubShim.callArgString(0, 1)` equals the input exactly, including length; the length
  argument (`callArgBits(0, 2)`) equals `s.length()` in UTF-16 **code units**, not code points -
  assert that explicitly for the surrogate-pair case, where the two differ.
* `callArgIsNull(0, 1)` is true only for `null`. The library collapses null and empty to the same
  `WTF::String`, but the ABI carries the distinction and the facade must pass `NULL` for `null`
  and a non-`NULL` zero-length pointer for `""`. Assert both; this is the one place the
  distinction is observable on the way in.
* The embedded NUL survives as three code units, not one. This is the hazard `GetStringUTFChars`
  had and the contract's UTF-16 choice removes; assert it rather than assume it.
* A lone surrogate passes through unchanged - no replacement character, no exception. The DOM can
  hold one, and a codec that "fixes" it is a behaviour change.

Strings out, one method per status:

* `WKJ_STR_OK`: program a value with `setReturnString`, call, assert the facade returns an equal
  `String`, for each input above.
* `WKJ_STR_NULL`: program `null` and assert the facade returns Java `null`, **not** `""`.
  Separately program `""` and assert `""`, not `null`. Out is where the two are distinguished.
* `WKJ_STR_OVERFLOW`: program a value longer than the facade's initial buffer; assert the facade
  retries and returns the whole string; and assert from the recording that it called the symbol
  exactly twice, the second time with `result_cap >= result_length` reported by the first
  (`callArgBits(i, 2)` on both records). A facade that retried without growing would hang; one
  that returned the truncated prefix would pass a naive assertion. Hence the call count and the
  capacity are asserted too.
* An empty programmed value with a zero-capacity buffer returns `WKJ_STR_OK`, not `OVERFLOW`.

An input longer than `Integer.MAX_VALUE` code units is not representable as a Java `String`, so
the "arrays > 2 GB" case from `jfx-ffm-testing` pattern 6 does not arise here; say so in a comment
rather than writing a vacuous test.

### 4.7 `WebKitExceptionSlotTest` - the exception slot (contract section 2.2)

* No-exception path: call a `THROWS` function with nothing armed, assert nothing is thrown and
  `exceptionPending() == 0`. Assert the facade made no extra downcall for the check
  (`callTotal()` grew by exactly one) - the zero-downcall no-exception path is the whole reason
  for the design, and a facade that called a helper to check it would still pass every other test.
* For each of `WKJ_EXC_DOM` (1), `WKJ_EXC_EVENT` (2), `WKJ_EXC_RANGE` (3), `WKJ_EXC_UNDEFINED` (4):
  `armException(symbol, type, code, message)`, call through the facade, assert the exception class
  is the one the JNI threw for that type, that its code equals `code`, and that `getMessage()`
  equals the message exactly - including a non-ASCII message and an empty message.
* Truncation: arm a 300-code-unit message and assert Java sees exactly `WKJ_EXC_MESSAGE_MAX`
  code units. Take that bound from the C table
  (`WkjStubShim.structFieldElements` of `WKJExceptionSlot.message`), not from a `256` literal
  duplicated in Java - the point is that the two agree.
* The message is inline in the slot and is **not** NUL terminated; `message_length` is
  authoritative. Arm a long message, throw, then arm a short one and assert no tail of the first
  leaks into the second. That failure mode is specific to an inline buffer and did not exist while
  the message was a pointer, so it is new and untested elsewhere.
* After the throw, Java clears the slot: `exceptionPending() == 0`, and the next call does not
  throw again.
* The library also clears the slot on entry to every `wkj_*` call: `WkjStubShim.raise(...)`
  directly, then make an unrelated facade call, then assert `exceptionPending() == 0`.
* Per-thread: arm on thread A, call the symbol on thread B; B does not throw and A's slot is
  untouched.
* Selectivity: a symbol whose spec row is not `THROWS` must not be exception-checked. Arm an
  exception on such a symbol, call it, assert nothing is thrown. (If the facade checks every call
  this fails: that is a performance defect rather than a correctness one - keep the assertion and
  say so in the failure message.)
* An unknown type value (99) must give a defined outcome, not a `NullPointerException`: assert the
  facade throws its documented fallback exception, naming the unknown type.

### 4.8 `WebKitRegistryTest` - the object registry (contract section 3, pattern 5)

* `register(o)` returns a non-zero id; `lookup(id) == o` (identity); two registrations of the same
  object return different ids or the same id - assert whichever the implementation documents, and
  say so in the test name.
* `unregister(id)`: `lookup(id) == null` afterwards, and a host upcall carrying the dead id is
  handled by logging, not by throwing (see 4.9).
* `lookup(0)` is `null` (0 is the null reference).
* Retain/release: fire `core.retain` then `core.release` through `WkjStubShim.fireHost` and assert
  the registry entry survives the first and disappears when the count reaches zero.
* Leak-emptiness: `registrySize()` before, then 10 000 register/unregister cycles, then
  `System.gc()`, then assert `registrySize()` is back to the starting value **exactly**. No
  tolerance; a registry that grows is the leak this test exists to find.
* Concurrency: 8 threads x 1000 register/unregister, then the same emptiness assertion.

### 4.9 `WebKitHostTableTest` - upcalls (pattern 4)

* After `installHostTable()`: `hostInstalled()`, `hostSize() == sizeOf("WKJHost")`,
  and for every slot Java is expected to fill, `hostSlotPointer(i) != 0`. Slots deliberately left
  `NULL` must be listed explicitly in the test, so adding a callback without wiring it fails here.
* For each installed slot: build `argv` for its signature (`hostSlotSignature(i)`), call
  `fireHost(i, args)`, assert status 0 and that the Java target recorded the call into a
  `CopyOnWriteArrayList` with the exact argument values, including a `float` and a `double`
  argument decoded from raw bits and a `wkj_ref` round-tripped through the registry.
* Return values: a slot with a non-`void` return gives the value the Java target returned, decoded
  from `lastFireResult()`.
* **Throwable containment**: install a target that throws, fire it, assert (a) the JVM survives,
  (b) `fireHost` returns 0 and the documented default value, (c) the message reached the logger -
  capture it with a `PlatformLogger` handler rather than asserting on stdout. Tag
  `@Tag("crash-prone")`; if the target failed to catch, this test takes the JVM down and surefire
  reports the fork death, which is the intended loud failure.
* **Foreign thread**: `fireHostOnForeignThread(slot, args)` must reach the same Java target from a
  thread the JVM has never seen, with no attach step. Assert the recorded
  `Thread.currentThread()` is not any JVM thread that existed before the call.
* **No upcall after dispose**: `clearHost()`, then `fireHost(...)` returns `-4` and nothing is
  recorded. Re-install in `@AfterEach`.
* A `NULL` slot returns `-2` and does not crash - the contract requires the library to tolerate
  `NULL` entries.

### 4.10 `WebKitArenaLifetimeTest` - lifetime and confinement (pattern 5)

* `assertThrows(IllegalStateException.class, ...)` when a facade call is handed
  `WkjStubShim.allocateClosedSegment()`; assert the message mentions the closed session.
* `assertThrows(WrongThreadException.class, ...)` when `allocateConfinedSegment()` is touched from
  another thread.
* The host table's arena is process-lifetime: assert `hostSlotPointer(i)` is still valid after
  `System.gc()` and a forced allocation churn, by firing a slot again and seeing the target run.
* Per-call scratch arenas do not leak. Assert this deterministically, not by watching memory: add
  a package-private counter to `WebKitNative` that increments on every per-call `Arena` open and
  decrements on close, expose it as `WebKitNativeShim.openArenaCount()`, run 100 000
  string-argument calls and assert the count is back to its starting value. A committed-memory
  assertion would flake, and a flaky test here is worse than none.

### 4.11 `WebKitDomFacadeTest` - one real downcall per shape (pattern 3)

One test method per return/parameter shape in the DOM ABI, each calling the generated facade and
asserting the recording, so that every code path the facade generator emits is executed at least
once:

| Shape | Representative symbol |
|---|---|
| `void (int64_t)` | `wkj_dom_Node_dispose` (or the spec's current dispose symbol) |
| `int32_t (int64_t)` | `wkj_dom_Attr_getSpecified` |
| `int64_t (int64_t)` | `wkj_dom_Attr_getOwnerElement` |
| `int16_t (int64_t)` | `wkj_dom_Node_getNodeType` |
| `float (int64_t, int16_t)` | `wkj_dom_CSSPrimitiveValue_getFloatValue` |
| `double (int64_t)` | a `JAVA_DOUBLE` row from the spec |
| string out | `wkj_dom_Attr_getName` - `int32_t (int64_t, uint16_t*, int32_t, int32_t*)` |
| string in | `wkj_dom_Attr_setValue` - `void (int64_t, const uint16_t*, int32_t)` |
| multi-string | `wkj_dom_DOMImplementation_createDocumentType` (three string pairs) |

For each: program the return with `setReturn*`, call, assert the Java value equals what was
programmed (including negative values, `Integer.MIN_VALUE`, `-0.0`, `NaN` via
`Float.floatToRawIntBits`, and `Long.MIN_VALUE` for peers), and assert every recorded argument
equals what was passed. `-0.0` and `NaN` are there because a `float`/`double` that travels as raw
bits is exactly where a sloppy conversion hides.

### 4.12 `WebKitLibraryAbiTest` - the sentinel (see section 5)

Package `test.com.sun.webkit`, **not** tagged `ffm`, so it runs in the ordinary module execution
with the ordinary library. It has one job: when `-Djfx.web.skipTests=false` is passed, say in one
sentence whether the `jfxwebkit` on the library path implements the new ABI.

* Load the library the production path loads and look for `wkj_abi_version`.
* If absent, **fail** with a message naming the file that was loaded, the fact that it exports
  `Java_com_sun_*` JNI symbols instead, and the instruction to rebuild `jfxwebkit` from the
  migrated sources (`WEBKIT-MEDIA-STUBS.md`, `FFM-ABI-CONTRACT.md` section 8).
* If present but the version differs from `WKJ_ABI_VERSION`, fail naming both numbers.
* If present and matching, pass.

## 5. What to do about the 473 existing tests

**Recommendation: give the 473 an ABI-probe assumption, and add the non-skippable sentinel
`WebKitLibraryAbiTest` (4.12) next to it.**

### The trade-off

*Hard-failing as a forcing function* has one real virtue: nobody can forget. But the failure it
produces is 473 red tests with mixed causes - `UnsatisfiedLinkError: missing native symbol:
wkj_init` from most, timeouts from some, `NoClassDefFoundError` from the rest once a static
initializer has already failed once. A reviewer cannot tell that pile apart from a genuine
regression, which means after the first such run everyone stops reading it, and the forcing
function has already stopped working. It also makes the migration's own commits unreviewable:
"473 failing" is the same output whether the Java is perfect or broken.

*Assumption-skipping alone* has the opposite failure: a green build that verified nothing. That is
the pattern the fork's testing rules forbid, and rightly.

The combination avoids both. The suite is **not green** - the sentinel is red, once, with the
exact reason and the exact fix. The 473 report as *skipped*, which is the truth: they cannot be
evaluated, and pretending otherwise in either direction is worse. The instant `jfxwebkit` is
rebuilt, all 473 run again with no further edits, because the probe is a property of the loaded
library rather than a flag someone has to remember to flip.

### Concretely

Add to `WebKitNativeShim`:

```java
public static boolean abiAvailable();   // true when the loaded library exports a matching wkj_abi_version
public static String abiUnavailableReason();
```

and one line at the top of each class that needs the native library:

```java
@BeforeAll static void requireWebKitAbi() {
    assumeTrue(WebKitNativeShim.abiAvailable(), WebKitNativeShim::abiUnavailableReason);
}
```

The set of files is small because the suite already funnels through a base class:

* `test/javafx/scene/web/TestBase.java` - covers 34 of the 46 test classes;
* `test/javafx/scene/web/EventListenerLeakTest.java`, `test/com/sun/webkit/SharedBufferTest.java`,
  `test/com/sun/webkit/SimpleSharedBufferInputStreamTest.java`,
  `test/com/sun/webkit/text/TextBreakIteratorTest.java` - the standalone native users;
* nothing in `test/com/sun/webkit/network/**` or `DirectoryLockTest` - those are pure Java and
  must keep running unconditionally. Do not add the assumption there; if one of them starts
  needing the library, that is a regression in the test, not a reason to skip it.

Constraints on the change:

* The assumption goes in `@BeforeAll`, so a class either runs entirely or skips entirely - a
  half-skipped class with a broken `@BeforeEach` is the confusing outcome we are avoiding.
* No `@Disabled` anywhere. No `unstable.test` gate either: these tests are not unstable, they are
  unevaluable, and the two must not be conflated.
* The assumption and the sentinel are **removed in the same commit that lands a rebuilt
  `jfxwebkit`**, and that commit must show the 473 passing again. Write that requirement into the
  commit message of the commit that adds them, so the debt is recorded where it will be seen.
* The probe must be a symbol lookup, not a `try { new WebPage() } catch`. A broad catch would also
  swallow a real initialisation bug and skip the suite for the wrong reason.

### `tests/system` robot web tests

`PointerEventTest`, `TextSelectionTest`, `TooltipFXTest` in
`tests/system/src/test/java/test/robot/javafx/web/`. They are already doubly opt-in
(`-DFULL_TEST=true -DUSE_ROBOT=true`), CI never runs them, and they need a display **and** a real
rendering WebView - `wkjstub` cannot help them, since a recording stub renders nothing.

* **Leave them hard-failing.** No assumption. Two explicit flags are already a strong enough
  forcing function, and a developer who passes both has asked for the real thing.
* They must be run, on a machine with a display, once `jfxwebkit` is rebuilt, on **each** of
  Windows, Linux and macOS, and the result recorded in the PR:
  `mvn -pl tests/system test -DFULL_TEST=true -DUSE_ROBOT=true -Dtest='test/robot/javafx/web/**'`.
  They cover the paths `wkjstub` structurally cannot: pointer-event delivery through
  `WebPage`'s upcalls into `WebView`, text selection through the editor client, and tooltips
  through the chrome client - three of the host-table groups that are still `reserved`
  placeholders today.
* `tests/system` needs no wiring change for this migration: its argLine already carries
  `--enable-native-access=javafx.graphics,javafx.media,javafx.web` and
  `--add-exports javafx.web/com.sun.webkit=ALL-UNNAMED`.
* DumpRenderTree stays the deeper net for phases B-D and is a manual run against a WebKit build;
  record the exact command in the PR (`jfx-web-native`, "Build & test").
